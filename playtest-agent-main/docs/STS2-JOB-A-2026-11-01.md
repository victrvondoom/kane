The rules and pass marks for the paced recheck were committed before any paced result: commit 27f28fd, `docs/PACED-REPLAY-RULES-2026-11-01.md`.

## What the checks still get wrong

- `sts2-room-g-6` step 18 is a true report that neither check confirmed. With pacing, both replays reach 66/80. The agent reported at step 18, and the check keeps only the last 12 steps. The first kept picture already shows 66/80, so the rise from 56 is not in the pictures. Nothing was tuned for this.
- `sts2-room-g-8` step 30 was stopped by the refused input rule only by chance. Its text mentions Esc in passing, and its main claim is about a map click. The judge never saw it, so this run does not show what the judge would do.
- The refused input rule was added after an earlier false report. It stops a fault we already know. It is not proof against new faults.
- Pacing is on `confirm` only. The fix tools and the other replay tools still replay with no pace.
